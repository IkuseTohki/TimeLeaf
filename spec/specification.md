# TimeLeaf 全体仕様書

## 1. 概要

TimeLeafは、ネットワークが制限された環境下でも効率的にプロジェクト管理を行うためのデスクトップアプリケーションである。
本仕様書は、TimeLeafが提供する機能の全容、およびその背後にある設計思想を俯瞰するためのインデックスとして機能する。

TimeLeaf の最大の特徴は、データベース（RDBMS）を使用せず、ファイルを介した独自のデータ同期アプローチによって、オフライン環境下でのチームコラボレーションを実現することにある。

## 2. システム構成

TimeLeafは、データの永続化と同期を「フォルダベースのストレージ」によって解決している。
各仕様の詳細については、以下のカテゴリ別仕様書を参照されたい。

### 2.1. 業務ドメイン（Management）

プロジェクトの管理項目や、日々の進捗をどのように計測するかを定義する。

- [**プロジェクト・タスク管理仕様書**](./Management/ProjectAndTask.md): 管理項目、工数、見積、実績の定義。

### 2.2. システム基盤（System）

オフラインでの同期、データの保存形式、およびコンフリクトの解決策を定義する。

- [**データストレージ・同期仕様書**](./System/DataStorage.md): ファイル構成、JSON形式、Last Writer Winsルール。

### 2.3. ユーザーインターフェース（UI）

「森」や「樹」の成長を感じさせる世界観と、効率的な業務操作を両立するための画面構造を定義する。

- [**ワークスペースUI構造設計書**](./BaseDesign/WorkspaceUIStructure.md): ナビゲーション、コンポーネント分割、データ同期方針。

### 2.4. ターゲット・プラットフォーム

多様な実行環境（とくに古いシステムが残るオフライン環境）に対応するため、マルチターゲット設計を採用している。

- **メイン環境**: .NET 10 (WPF) - 最新の言語機能とパフォーマンスを最適化。
- **互換環境**: .NET Core 3.1 (WPF) - レガシー環境や特定の制約があるシステムへの対応。

## 3. 主要機能のビジョン

TimeLeafが提供する主要な機能は、単なるツールの提供に留まらず、チームの「リズム」を作ることを目的としている。

### 3.1. 計画と可視化

単なる「ToDoの羅列」ではなく、プロジェクトの健全性を多角的に可視化し、意思決定を支援する。

- **ALL TASKS**: 全プロジェクトを横断して、すべてのタスクを一覧表示・フィルタリングする機能。
- **マルチビュー**: カンバン、リスト、ガントチャート等、用途に応じた視点。
- **見積と実績の対比**: 計画の精度を可視化し、将来の改善へ繋げる。

### 3.2. コラボレーションと同期

ネットワークがなくても、情報の鮮度を保ち、チームの意思疎通を支える。

- **インライン・コメント**: タスクごとの蓄積型ディスカッション。
- **オフライン同期**: ファイル共有による、不整合のないデータ共有。

### 3.3. 通知システム (Alerts & Notifications)

チームメンバーからの更新や、差し迫ったデッドラインを見逃さないよう、ユーザーの状況に応じた多層的な通知機能を提供する。

- **スナックバー**: アプリ操作中の即時フィードバック。操作を妨げない非破壊的な通知。
- **通知センター**: 期限切れタスクの履歴管理。サイドバーのバッジにより未確認数を一目で把握可能。
- **OS標準通知**: アプリが背面に隠れている、あるいはトレイに常駐している際にも気づける Windows Toast 通知。

### 3.4. 常駐とバックグラウンド動作

ウィンドウを閉じてもタスクバー（システムトレイ）に常駐する。これにより、外部からのファイル同期（他メンバーの更新）をバックグラウンドで検知し、リアルタイムに通知を行うことが可能となる。

## 4. 非機能要件

- **オフラインファースト**: ネットワーク環境に依存せず、常にローカルですべての操作が可能であること。
- **ポータビリティ & 互換性**: インストール不要、あるいは最小限の構成で動作し、データそのものが持ち運び可能であること。また、.NET Core 3.1 等の古いランタイム上でも同一の業務ロジックが動作することを保証する。
- **透過性**: データの形式（JSON）が人間にも理解可能であり、ツールのロックインを避けること。
