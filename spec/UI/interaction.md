# UI 仕様：インタラクション・振る舞い

## 1. モーダルインタラクション

設定画面や詳細ダイアログの表示時において、ユーザーの注意を現在のアクションに集中させ、誤操作を防ぐための挙動を定義する。

### 1.1. 視覚的効果とブロック

モーダル表示の際は、背面への入力をブロックするため、メインウィンドウ全体を半透明のレイヤー（シャドウ・オーバーレイ）で覆う。これにより、ユーザーは「現在のアクションを完了させる必要がある」ことを直感的に理解する。

- **オーバーレイ**: 黒色（不透明度 30% 前後）のフェードイン。
- **キャンセル挙動**: ウィンドウ外（オーバーレイ領域）のクリック、あるいは `Esc` キーの押下によってモーダルを閉じる動作を原則としてサポートする。

### 1.2. アニメーションとフォーカス

ウィンドウの出現時は、静的な表示ではなく、動きを伴うことで「どこから現れたか」を意識させる。また、キーボード操作の連続性を保つため、適切なフォーカス制御を行う。

- **出現アニメーション**: 下から上へのわずかなスライドと、スケールアップを伴うフェードイン。
- **フォーカストラップ**: モーダル内での `Tab` キー移動をループさせ、背面の要素へフォーカスが漏れるのを防ぐ。

## 2. 通知インタラクション

プロジェクトの状態変化を適切に伝えつつ、ユーザーの思考を中断させない「控えめな通知」と「確実な報知」の両立を目指す。

### 2.1. スナックバー（一時的通知）

操作の直後や、バックグラウンドでの軽微な成功・エラーを伝えるために使用する。メインの作業領域を侵食しないよう、画面下部の中央に配置する。

- **出現タイミング**: データの保存完了、設定の適用、期限切れタスクの初回の検知時。
- **表示持続時間**: 通常 5 秒。エラーなどの重要な情報は 10 秒以上。
- **アニメーション**: 下から 20px ほどスライドアップしながらフェードイン。消去時はフェードアウト。

### 2.2. システムトレイと OS 通知

アプリが背面に隠れている、あるいは閉じられている状態でも、重要なタイミングでのみユーザーの介入を促す。

- **OS 標準通知**: 他の作業を妨げないよう、Windows 標準の通知バナー（Toast）として送出。クリックによってアプリを前面に復帰させ、関連する要素へナビゲートする。
- **トレイアイコンのバッジ**: （将来拡張）未読通知がある場合、アイコン上にドットや数字を表示し、静的に情報の存在を知らせる。

## 3. アプリケーションの常駐と復帰

TimeLeaf を「常に動いているプロジェクトの監視役」として位置づけるため、従来のアプリケーションとは異なる終了プロセスを採用する。

### 3.1. ウィンドウの非表示化

通常の「×」ボタンは、アプリケーションの「プロセス終了」ではなく「UI の非表示（Hide）」として扱う。これにより、起動時間をゼロにし、通知機能を継続させる。

- **閉じるボタンの挙動**: メインウィンドウを非表示にし、システムトレイへの格納状態へ移行する。
- **最小化との違い**: 最小化はタスクバーに残り、非表示化は通知領域のみに残る。

### 3.2. システムトレイでの操作

トレイアイコンは、アプリケーションの状態を制御する「外部リモコン」として機能する。

- **ダブルクリック**: ウィンドウを最後に開いていた状態で再表示し、フォーカスを当てる。
- **右クリックメニュー**:
  - **TimeLeaf を開く**: ウィンドウを表示。
  - **（セパレーター）**:
  - **終了**: すべての変更をディスクにフラッシュし、プロセスを完全に終了する。
