# プロジェクト・タスク管理仕様書

## 1. 概要

TimeLeafは、ネットワークが制限された環境下でのチーム開発を支えるプロジェクト管理ツールである。
本仕様書では、プロジェクト全体および個別のタスクにおいて、どのようなデータが管理され、それらがどのような意味を持つのかを定義する。

とくに、オフラインでの「計画と実績」の可視化を重視しており、各データ項目は、将来の計画精度を向上させるための指標となることを目的としている。

**※ 日時データの取り扱いについて**

システム内部（計算、比較、保存）およびUI表示におけるすべての日時データは、日本国内での運用を前提とし、JST（日本標準時 / UTC+9）に統一して管理する。これにより、保存データと表示の不一致を完全に排除する。

## 2. プロジェクト管理項目

プロジェクトは、チームが共通の目標に向かって進むための最上位の管理単位である。
TimeLeafでは、プロジェクトをひとつの「箱」として捉え、その目的と健全性を維持するために以下の項目を保持する。

- **プロジェクト名**: チーム全体でプロジェクトを識別するための名称。
- **説明**: プロジェクトの目的や概要を記述する。
- **マイルストーン**: プロジェクトの節目となる重要な目標。日付とラベルのセット。
- **状態**: プロジェクトが現在どのような段階にあるか（準備中、進行中、完了、一時停止など）。
- **最終更新日時 (UpdatedAt)**: プロジェクトの変更が最後に「正常に保存（ファイル出力）」された時刻。メモリ上の変更のみでは更新されず、ディスクへの書き込み成功を以て確定する。

## 3. タスク管理項目

タスクは具体的な作業単位であり、TimeLeafにおける日々の活動の主体となる。
タスクは単なる「ToDo」に留まらず、工数管理（見積と実績）や依存関係の管理を通じて、プロジェクトの健全性を精緻に測定するための基盤となる。

### 3.1. 基本属性

タスクの性質や担当を定義するための中心的な項目である。

- **タスク名**: 作業の内容を一目で理解できる名称。
- **担当者**: そのタスクに対して責任を持つメンバー。
- **状態**: 作業の進捗状況（未着手、着手中、レビュー待ち、完了など）。
- **制約 (Constraints)**: タスク間の論理的な順序性。以下の4つの型をサポートする。
  - **FS (Finish-to-Start)**: 先行タスクの完了後に、このタスクを開始できる（もっとも一般的）。
  - **SS (Start-to-Start)**: 先行タスクの開始後に、このタスクを開始できる。
  - **FF (Finish-to-Finish)**: 先行タスクの完了時に、このタスクを完了させていなければならない。
  - **SF (Start-to-Finish)**: 先行タスクの開始時に、このタスクを完了させていなければならない。
- **依存タスク (Predecessors)**: このタスクが制約を受ける先行タスクのリスト。

### 3.2. コンテナ（サマリータスク）の挙動

タスクが子タスクを保持する場合、そのタスクは「コンテナ」として振る舞い、個別の作業実体ではなく管理単位としての役割を持つ。

- **自動集計**: 開始日、期限、進捗率は、配下の子タスクのデータに基づいて自動的に算出・集計される。
- **カプセル化**: グラフィカルな表示において、コンテナ単位での「折りたたみ」を可能とし、詳細を隠蔽した状態での全体進捗の把握（マクロ視点）を提供する。
- **制約の継承**: コンテナ自体に制約が設定された場合、その影響は配下の子タスク全体に波及する。

### 3.3. スケジュールと工数

計画と現実のギャップを把握するために、見積（期待値）と実績（実測値）の両面から管理を行う。

- **開始予定日**: 作業を開始することを想定している日付。
- **期限 (Due Date)**: タスクを完了させなければならない目標日。
- **見積（初回）**: 作業開始前に想定した工数（時間または日）。
- **見積（修正後）**: 予期せぬトラブルや仕様変更により、計画を見直した後の工数。
- **実績**:
  - **開始日 / 終了日**: 実際に作業に着手した日、および完了した日。
  - **実績工数**: 実際にそのタスクに費やした累積時間。

## 4. コンテキスト別の編集権限

タスクの属性は、操作を行う場所（コンテキスト）によって、直接編集が可能か、あるいは参照のみに制限されるかが決まります。これにより、意図しない書き換えを防ぎつつ、日々の更新作業を効率化します。

### 4.1. クイック・サイドパネルでの振る舞い

サイドパネルは「今この瞬間の実績」を記録するための場所です。そのため、計画値の変更などは行えず、実績に関わるプロパティのみが入力可能となります。

- **編集可能項目**: ステータス（進捗）、実績開始日、実績終了日、実績工数
- **参照専用項目**: タスク名、優先度、開始予定日、期限、見積工数、担当者
- **非表示項目**: 詳細説明、コメント履歴、依存関係、添付ファイル

### 4.2. 詳細ウィンドウでの振る舞い

詳細ウィンドウは、タスクの「完全な支配」を目的としています。ここでは、管理権限を持つユーザー（または担当者）が、計画の修正を含むすべての項目を自由に編集・閲覧できます。

- **編集可能項目**: すべての属性（タスク名、説明、優先度、全スケジュール、全工数、担当者、依存関係）
- **対話項目**: 全コメント履歴の閲覧および新規コメントの投稿
- **管理項目**: 添付ファイルの追加・削除
