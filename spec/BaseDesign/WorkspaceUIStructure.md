# ワークスペースUI構造設計書

## 1. 目的

本ドキュメントでは、プロジェクト内での実務および進捗把握を最適化するため、現在の集約型UI（ProjectWorkspaceView）を分割・再構築する方針について定義します。
単なる機能の分離に留まらず、TimeLeaf の世界観である「森」や「樹」の成長を感じさせるオーガニックなユーザー体験と、効率的な業務操作の両立を目的としています。

---

## 2. ナビゲーション構造

ユーザーがプロジェクトの全体像（マクロ）と個別の作業（ミクロ）をスムーズに行き来できるよう、左サイドバーによるナビゲーション構造を採用します。

### 2.1. オーガニック・サイドバー

サイドバーは、プロジェクトの「幹」として、各機能（枝）への入り口を提供します。画面領域を有効活用するため、以下の 2 つの状態を持ちます。

- **展開状態**: アイコンとラベルを表示し、はじめてのユーザーでも迷わない視認性を提供。
- **折りたたみ状態**: アイコンのみを表示。タスク操作などの広い作業領域が必要な場面に適応。

### 2.2. ナビゲーション項目

サイドバーに配置する主要な切り替え項目は以下の通りです。

- **Dashboard**: プロジェクトの健康状態を俯瞰するための概要画面。
- **Tasks**: ステータス管理、詳細編集を行う実務画面。
- **Timeline**: タスクの前後関係を時系列で俯瞰するガントチャート画面。
- **Notifications**: 期限切れや更新情報の履歴を確認する通知センター。
- **Settings**: アーカイブ、エクスポートなどのプロジェクト管理設定。

---

## 3. 主要コンポーネントの定義

大規模な画面を、関心事（責任範囲）ごとに以下のコンポーネントに分割します。これにより、コードの保守性とデータの読み込み効率を向上させます。

### 3.1. ProjectDashboardView（戦略的視点）

プロジェクトを育てている実感を醸成し、次に目指すべき目標を明確にするための画面です。

- **樹の成長ビジュアル**: 進捗率（％）を樹の高さや葉の密度として視覚化。
- **プロジェクトの根源**: プロジェクトの目的（Roots）を表示。
- **マイルストーンの小道**: 垂直な点線グラフで、将来の主要な節目をリスト表示。

## 3. 主要コンポーネントの定義

### 3.1. ProjectTasksView（戦術的視点：スプリット・コンテナ）

タスクの実行と構造の把握を両立するため、コンテナ内を左右に分割したレイアウトを採用する。

- **左側：ミニマル・タスクリスト（ミクロ管理）**:
  - **引き算のデザイン**: 非選択状態のタスクは、テキストと境界線のみの極めてシンプルな表示に留める。
  - **段階的情報開示**: 選択されたタスクのみが「カード」として浮き上がり、担当者・期限・ステータス等の詳細情報と編集インターフェースが展開される。
- **右側：グラフィカル・フロー図（マクロ把握）**:
  - **インタラクティブ・ノード**: 各タスクをノードとして表示し、マウスドラッグによる自由な配置換えが可能。
  - **制約の可視化**: タスク間の依存関係を線で結ぶ。正常な制約は細い線、制約違反（循環参照や遅延リスク）は赤い太線やパルス表示で強調する。

### 3.2. タスク提示の多層化：サイドパネルと詳細ウィンドウ

（既存の定義を維持）

### 3.3. 通知・リスク報知システム（Notification Pane）

「引き算のデザイン」に基づき、ユーザーの作業を妨げずに重要なリスクを伝える。

- **シームレス・通知ペイン**: 画面右端から背景に溶け込むように配置された、半透明の通知エリア。
- **リスクの段階的表現**:
  - **警告 (Warning)**: オレンジ色のテキストで遅延の予兆などを通知。
  - **異常 (Error)**: 赤色のテキストで循環参照などの深刻な論理矛盾を通知。
- **お天気アイコン (Project Weather)**: 右下に配置される小さなインジケーター。クリティカルパス上のリスクを「雷雨」などの天気アイコンで象徴的に表示し、チームに現在の「空気感」を共有する。

## 4. デザイン哲学：引き算のデザイン (Subtractive Design)

TimeLeaf の UI における最上位の指針である。

- **ノイズの排除**: 常に表示されるボタンや装飾を最小限に抑え、余白とタイポグラフィを主役とする。
- **コンテキストに応じた浮上**: ユーザーが操作を意図した瞬間（選択やホバー）にのみ、必要なコントロールを「浮かび上がらせる」。
- **意味のあるアニメーション**: 状態の変化やリスクの発生を、パルスや滑らかなスライドインで表現し、静かな画面の中での「気づき」を最大化する。

---

## 4. アプリケーションの常駐とライフサイクル

TimeLeaf は「常に最新の状況を把握する」ため、従来のデスクトップアプリとは異なる終了挙動を持ちます。

### 4.1. システムトレイ（通知領域）への常駐

ウィンドウの「×」ボタンを押しても、アプリケーションは終了せずタスクバーの通知領域に常駐（Hide）します。これは、他メンバーからの同期ファイルをバックグラウンドで監視し続け、重要な通知をリアルタイムに届けるためです。

### 4.2. 終了と再開のフロー

- **再開**: トレイアイコンのダブルクリック、または右クリックメニューの「開く」により、直前の状態（開いていたプロジェクト等）を保持したまま瞬時にウィンドウを再表示。
- **完全終了**: トレイアイコンの右クリックメニュー「終了」を選択した場合のみ、メモリ上のデータを保存し、プロセスを終了。

## 5. ViewModel 階層とデータフロー

UI の分割に合わせ、ViewModel も親子階層構造へと移行します。

### 5.1. 階層構造

`ProjectWorkspaceViewModel` を親とし、各サブビューに対応する ViewModel を動的に切り替えます。

- **Parent**: `ProjectWorkspaceViewModel`
  - **CurrentSubView**: `ProjectDashboardViewModel`, `ProjectTasksViewModel` 等を適宜保持

### 5.2. 状態の共有と同期

各サブ ViewModel が一貫したデータを保持するため、以下の同期ルールを適用します。

- **共有モデルの注入**: 親が保持する `ProjectViewModel` (Shared State) の参照を全サブ ViewModel に注入。
- **リアクティブ更新**: モデルの変更を検知し、すべてのサブビューが即座に最新状態を反映。
- **自動保存の集約**: 各サブビューでのプロパティ変更は、`ProjectSaveCoordinator` が一括して検知し、保存を実行。
