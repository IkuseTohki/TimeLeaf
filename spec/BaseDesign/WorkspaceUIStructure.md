# ワークスペースUI構造設計書

## 1. 目的

本ドキュメントでは、プロジェクト内での実務および進捗把握を最適化するため、現在の集約型UI（ProjectWorkspaceView）を分割・再構築する方針について定義します。
単なる機能の分離に留まらず、TimeLeaf の世界観である「森」や「樹」の成長を感じさせるオーガニックなユーザー体験と、効率的な業務操作の両立を目的としています。

---

## 2. ナビゲーション構造

ユーザーがプロジェクトの全体像（マクロ）と個別の作業（ミクロ）をスムーズに行き来できるよう、左サイドバーによるナビゲーション構造を採用します。

### 2.1. オーガニック・サイドバー

サイドバーは、プロジェクトの「幹」として、各機能（枝）への入り口を提供します。画面領域を有効活用するため、以下の 2 つの状態を持ちます。

- **展開状態**: アイコンとラベルを表示し、はじめてのユーザーでも迷わない視認性を提供。
- **折りたたみ状態**: アイコンのみを表示。タスク操作などの広い作業領域が必要な場面に適応。

### 2.2. ナビゲーション項目

サイドバーに配置する主要な切り替え項目は以下の通りです。

- **Dashboard**: プロジェクトの健康状態や目的を愛でるための概要画面。
- **Tasks**: 日々のタスク操作、ステータス管理、詳細編集を行う実務画面。
- **Timeline**: マイルストーンやタスクの前後関係を時系列で俯瞰するガントチャート画面。
- **Settings**: 名称変更やアーカイブ、エクスポートなどのプロジェクト管理設定。

---

## 3. コンポーネント定義

大規模な画面を、関心事（責任範囲）ごとに以下のコンポーネントに分割します。これにより、コードの保守性とデータの読み込み効率を向上させます。

### 3.1. ProjectDashboardView（戦略的視点）

プロジェクトを育てている実感を醸成し、次に目指すべき目標を明確にするための画面です。

- **樹の成長ビジュアル**: 進捗率（％）を樹の高さや葉の密度として視覚化。
- **成長統計（プログレスリング）**: 「完了作業」「消費エネルギー（工数）」「期限までの日数」を円グラフで直感的に提示。
- **プロジェクトの根源**: プロジェクトの目的（Roots）を表示し、常に原点に立ち返れるように配置。
- **マイルストーンの小道**: 垂直な点線グラフで、過去から未来への主要な節目をリスト表示。

### 3.2. ProjectTasksView（戦術的視点）

タスクの実行に集中するための画面です。

- **タスクボード**: リスト形式またはカンバン形式によるタスクの一覧表示。
- **操作インターフェース**: 新規タスクの素早い追加、フィルタリング、および検索。
- **詳細への導線**: タスクを選択することで、後述する詳細パネルを呼び出し。

### 3.3. TaskDetailPanel（対話的視点）

1 つのタスクに対する深い理解と、チーム内での非同期コミュニケーションを担います。本コンポーネントは Tasks 画面の右側からスライド、あるいは独立したパネルとして表示されます。

- **属性編集**: 説明文（Markdown）、優先度、担当者、スケジュール、工数実績の入力。
- **ディスカッション**: インクリメンタル（蓄積型）なコメント投稿と、履歴の表示。
- **依存関係管理**: 前後の関連タスクとの繋がりを設定。

## 4. ViewModel 階層とデータフロー

UI の分割に合わせ、ViewModel も親子階層構造へと移行します。

### 4.1. 階層構造

`ProjectWorkspaceViewModel` を親とし、各サブビューに対応する ViewModel を動的に管理します。

- **Parent**: `ProjectWorkspaceViewModel`
  - **CurrentSubView**: 以下のいずれかを保持
    - `ProjectDashboardViewModel`
    - `ProjectTasksViewModel`
    - `ProjectTimelineViewModel`

### 4.2. 状態の共有と同期

各サブ ViewModel が一貫したデータを保持するため、以下の同期ルールを適用します。

- **共有モデルの注入**: 親が保持する `ProjectViewModel` (Shared State) の参照を、コンストラクタ経由で全サブ ViewModel に注入。
- **リアクティブ更新**: 第 25 ステップで実装した差分更新（`UpdateFromModel`）を活用。外部からのファイル同期が発生した際、すべてのサブビューが同一の Model インスタンスを通じて即座に最新状態を反映。
- **自動保存の集約**: 各サブビューでのプロパティ変更は、`ProjectViewModel.PropertyChanged` を通じて `ProjectSaveCoordinator` が検知し、一括して保存ユースケースを実行。
