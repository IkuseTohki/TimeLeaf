# ボタン仕様 (Buttons)

## 1. 状態遷移と視覚的フィードバック (State & Visual Feedback)

Soft Emphasis規約（静謐な背景）に基づき、ボタンに対するユーザーのインタラクションには、以下の微細な視覚的フィードバックを提供する（MUST）。

- **通常時 (`Normal`):** 定義されたベースカラーまたはトランスペアレント（透明）を適用する。
- **ホバー時 (`Hover`):** 操作の予兆を示すため、以下のいずれかを適用する。
  - ベタ塗りボタンの場合: ベースカラーの輝度（Lightness）を 10% 変更（明るく、または暗く）する。
  - ゴーストボタン等の場合: `StateHoverBrush`（低不透明度のグレー）を背景に重ねる。
- **押下/実行時 (`Active` / `Pressed`):** 物理的に押し込まれた感覚を表現するため、要素全体の不透明度（Opacity）を `90%` に下げる（MUST）。

## 2. ダイアログにおける配置ルール (Dialog Button Placement)

UXデザイン原則の「予測可能性（標準への準拠）」に従い、Windowsデスクトップアプリケーションとしての標準的なメンタルモデルに合わせたボタン配置を徹底する（MUST）。

### 2.1 肯定と否定の順序

- ダイアログ下部のアクションボタンは、**必ず左側に「肯定アクション（保存、OK等）」、右側に「否定アクション（キャンセル、閉じる等）」を配置する（MUST）。**
- **アライメント:** ボタングループ自体は、ダイアログの「右下」に右揃え（Right Alignment）で配置する。

**【レイアウト例】**
`[ ＿＿＿＿＿＿＿＿＿＿＿ [ 保存する ] [ キャンセル ] ]`

### 2.2 視覚的な階層（Primary / Secondary）

ダイアログ内に複数のボタンが存在する場合、ユーザーの視線を迷わせないため、視覚的な重み（Visual Weight）に明確な差をつける（MUST）。

- **Primary アクション（保存、決定など）:** `Theme.Colors.BrandPrimary`（アクセント色）のベタ塗りとし、もっとも目立たせる。
- **Secondary アクション（キャンセルなど）:** 背景を透明または `SurfaceBase` に近い色とし、枠線（Outline）またはテキストの色のみで表現する「ゴーストボタン」とする。

### 2.3 破壊的アクション (Destructive Action)

プロジェクトの削除など、取り返しのつかない「破壊的アクション」を肯定とするダイアログの場合に限り、Primaryアクションのボタン色をアクセント色ではなく `Theme.Colors.Error` 赤系）として警告を促す（MUST）。
