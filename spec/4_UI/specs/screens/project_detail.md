# プロジェクト詳細画面 (Project Detail)

個別のプロジェクトを選択した際に表示されるメイン作業領域。目的の情報を素早く引き出せるよう、以下の6つのサブビューを提供する（MUST）。
`Dashboard`, `Tasks`, `Flow`, `Timeline`, `Notifications`, `Settings`

---

## 1. Dashboard ビュー

プロジェクトの全体像と直近の目標を視覚的に把握するための入り口となる画面。  
「ツールは静謐な背景であるべき」という世界観に基づき、以下のオーガニックなメタファーを取り入れた構成要素を配置する（MUST）。

### 1.1 プロジェクトの根源 (Roots)

プロジェクトの「なぜ（Why）」を常にチームの視界に留めておくためのセクション。

- **表示内容:** プロジェクトの目的や背景（メタデータの `Description` に該当する要素）を表示する。
- **デザイン要件:** 強い装飾は避け、タイポグラフィの余白と文字サイズのみを用いて静かに配置する。

### 1.2 マイルストーンの小道 (Milestone Path)

プロジェクトが辿るべき将来の重要な節目を、道標として視覚化するセクション。

- **表示内容:** 予定されているマイルストーンの一覧を時系列で表示する。
- **デザイン要件:** 「垂直な点線グラフ」と「ノード（アイコンやドット）」を組み合わせたタイムラインUIを用いて表現する（MUST）。

## 2. Tasks ビュー (タスク操作・局所フロー)

プロジェクト内のタスク入力と直近の構造整理を行う画面。「引き算のデザイン」に基づき、画面を左右に分割するスプリット・レイアウトを採用する（MUST）。

### 2.1 左ペイン: ミニマル・リスト (List & Progressive Edit)

- **段階的情報開示:** 非選択時は極めてフラットで最低限のテキストのみを表示し、ユーザーがタスクを「選択」した瞬間にカード化して詳細な操作系（Quick Panel要素）を展開する（MUST）。
- **ノイズの排除:** 常時表示される罫線を削ぎ落とし、「余白」によって階層を表現する。

### 2.2 右ペイン: 局所的フロー (Local Flow Pane)

- 左ペインで選択した「コンテナ（サマリータスク）」の内部に限定して、タスク間の制約（Constraints）をグラフィカルに表示する。

---

## 3. Flow ビュー (全体構造・階層的フロー)

プロジェクト全体の有向非巡回グラフ（DAG）を描画し、大局的なボトルネックやクリティカルパスを分析・編集するための独立ビュー。

- **階層的表示:** 上位レベル（コンテナ同士の制約）から、下位レベル（タスク間の制約）へとシームレスに展開（ドリルダウン）して表示する機能を備える（MUST）。

### ※ Flow描画における共通インタラクション (Tasks右ペイン / Flowビュー共通)

- **ドラッグ接続:** ノードをマウスで移動・配置し、端からドラッグ＆ドロップで接続線を引くことで直感的に制約を構築・変更できる（MUST）。
- **リスクの視覚化:** 先行タスク未了等の制約破綻やクリティカルパスの遅延を、パルスアニメーション（ノードの静かな鼓動）や赤い接続線（`Theme.Colors.Error`）で強調表示し、実務のリスクを拾い上げる（MUST）。

## 5. Notifications ビュー (通知・警告層)

当該プロジェクトに限定された更新履歴やリスクを集約するビュー。旧来の独立ポップアップを廃止し、作業コンテキストを遮断しない背景透過型の「通知層（Pane）」として提供する。

- **リスクの拾い上げ:** 期限切れタスクの通知だけでなく、トポロジカルソートで検知された「制約の破綻（論理的矛盾）」も警告としてリストアップする（MUST）。

---

## 6. Settings ビュー (プロジェクト管理・設定)

プロジェクトのメタデータ管理、およびライフサイクルを制御するための専用ビュー。

- **メタデータの編集:** プロジェクト名、メンバー等の基本情報編集UI。
- **危険な操作 (Danger Zone):**
  - プロジェクトのアーカイブ（ADR-0002参照）
  - プロジェクトの削除（物理フォルダと全履歴の削除）
  - ※これらの操作実行時は、必ず確認ダイアログを挟まなければならない（MUST）。
