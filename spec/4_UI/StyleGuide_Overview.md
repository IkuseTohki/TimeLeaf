# UIスタイルガイド基本方針 (Style Guide Overview)

UIスタイルガイドは、デザインシステムの基本原則（Philosophy）とデザイントークン（Variables）を組み合わせ、具体的なUI部品として具現化した「見た目（What）」の見本帳である。
本ドキュメント群では、各コンポーネントが備えるべき構造、論理的な数値、および振る舞いの詳細を規定し、実装者が迷わずにインターフェースを構築するための基準を定める。

## 1. 記述すべき必須要件 (Required Specifications)

スタイルガイドは単なるビジュアル（画像）の提示に留まらず、以下の具体的な「仕様データ」を網羅しなければならない（MUST）。

### 1.1 トークンに基づく構造定義

- コンポーネントのサイズ、余白（Margin/Padding）、タイポグラフィ（フォントサイズ、行間、太さ）は、直接的な物理値ではなく、**必ず「デザイントークン（例: `Spacing.Medium`, `Font.Body`）」を用いて記述する（MUST）。**
- 色彩についても同様に、トークン名（例: `Color.Background.Primary`）を用いてセマンティクス（意味・用途）を明確にする（MUST）。

### 1.2 状態（State）別の振る舞い

あらゆるインタラクティブ要素（ボタン、入力フィールド等）は、以下の各状態における色・形状・透過度・枠線等の変化を詳細に規定する（MUST）。

- **通常時 (`Normal` / `Default`)**
- **ホバー時 (`Hover`):** ポインターが重なった状態
- **押下/実行時 (`Pressed` / `Active`):** クリックまたはタップされている状態
- **フォーカス時 (`Focus`):** キーボード等の操作フォーカスが当たっている状態（アクセシビリティ担保）
- **無効化時 (`Disabled`):** 操作を受け付けない状態
- **エラー時 (`Error` / `Invalid`):** バリデーションエラー等の異常をユーザーに通知する状態

### 1.3 インタラクションとアニメーション

- 状態変化に伴うトランジション（変化の所要時間、イージング曲線）を定量的な数値で定義する（MUST）。
- これにより、「パッと切り替わる」のか「滑らかにフェードする」のかの体感をシステム全体で統一する。

## 2. プラットフォーム非依存の原則 (Platform-Agnostic Principle)

本スタイルガイドは、特定のUIフレームワーク（WPF, React, Flutter, iOS/Android 等）に依存しない**「論理的なデザインスペック」**としての記述を基本とする（MUST）。

- **論理仕様と物理実装の分離:**
  ドキュメントの主文では「背景色は `Color.Primary`、角丸は `Radius.Small` とする」といった論理的なルールを記述する。
- **リファレンス実装の扱い:**
  特定のフレームワーク向けの実装コード（例: WPFのXAML `<Style>` 定義や、WebのCSSクラス）は、あくまでその論理仕様を具現化するための「リファレンス実装（例示）」としてドキュメント内に併記することを推奨する（SHOULD）。

## 3. UIドキュメント群の階層構造 (Directory Structure)

具体的なスタイル定義と画面設計は、役割や画面ごとに以下のドキュメント構造（またはそれに準ずるディレクトリ）へと展開して管理する。

```text
docs/4_UI/
├── DesignSystem_Principles.md      # 全プロジェクト共通のデザイン哲学
├── StyleGuide_Overview.md          # 【本ドキュメント】スタイルガイドの基本方針
│
├── tokens/                         # デザイントークン（対象プロダクト固有の変数値）
│   ├── colors.md
│   └── typography_spacing.md
│
└── specs/                          # 画面・コンポーネント仕様（対象プロダクト固有）
    ├── components/                 # 最小単位の部品定義（ボタン、入力欄 等）
    └── screens/                    # 画面ごとのレイアウト・コンポーネント配置見本
```
